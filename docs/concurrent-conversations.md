# 并发对话与批注派发

保存 / Git 工具栏右侧的 OpenCode、Codex、Claude Code 是后端入口。右侧对话栏的 + 创建一个新的独立会话；历史列表会打开或聚焦已有会话，不会替换正在执行的对话。相同后端可以同时打开多个会话。标签可横向滚动，悬停显示名称、后端、状态、会话 ID、草稿和队列提示。

切换标签或隐藏侧栏保留所有面板及其事件连接，每个会话独立拥有运行状态、权限、模型、输入草稿、Steer 和持久化队列。输入草稿与附件按项目和标签保存在本机，切换项目或重启后恢复。仍有对话在执行或等待批准时，切换项目或退出 Writer 会先确认；切换后任务在后台继续，退出会中断任务。标签列表按项目保存，重启后恢复原生会话历史。重启不会自动重放不确定的派发；待派发消息与恢复队列暂停，用户核对历史后再继续。正在执行、等待批准、有草稿或有队列的标签不能直接关闭。关闭空闲标签保留历史并注销协作入口。

批注菜单支持勾选多条、选择可见待处理、清空选择，并选择一个已打开的具体对话或新建任意后端的对话。提交前保存文档、批注和本地 Git 版本。目标忙碌时加入其队列；派发不使用或清空用户的输入草稿、图片或编辑器选区。AI 通过 Writer MCP 读取选文与最新 TeX 上下文，验证修改后标记解决并记录修改后的 Git 版本。已经解决的批注需重新打开才可再次提交。

这些会话共享同一个论文目录，能并行执行不同工作，但不是隔离工作树，也不承诺自动合并两个 Agent 同时改写同一段落的语义冲突。修改前需重新读取当前文件并保留其他修改；现有保存冲突检查与 Git 检查点继续生效。并发上限取决于本机内存及各模型订阅的并发限制，应用没有固定的角色分工或论文类型限制。

## 扩展接口

- `src/lib/harness/types.ts`：后端标识、标签元数据、派发目标和统一面板生命周期契约。
- `src/components/harness/workspace.tsx`：面板注册表、工具栏入口、滚动标签和常驻面板宿主。
- `src/lib/harness/use-panel-lifecycle.ts`：统一状态上报、外部任务接收与忙碌队列处理。
- `src/lib/harness/use-workspace.ts`：按项目恢复标签、去重历史会话、保存派发记录。
- `src-tauri/src/commands/harness.rs`：原生后端标识；Writer MCP 按该标识选择适配器。

添加后端时实现生命周期契约、注册面板和原生适配器；批注界面从同一个后端目录读取选项，无需复制按钮逻辑。Claude Code 使用自身 stream-json 协议和登录，通过 HTTP MCP 配置接入 Writer；临时认证令牌通过子进程环境变量传递，不写入项目或命令行参数。配置方式参考 [Claude Code MCP 文档](https://code.claude.com/docs/en/mcp)。

OpenCode 同项目多个对话共享一条 SSE 连接，避免触发浏览器每来源连接数上限；独立会话仍有自己的状态与消息存储。所有请求都带 `directory` 参数，一个 OpenCode 服务同时服务多个项目，打开其他项目不会重启服务、中断正在执行的会话。连接中断后若无法确认上一条排队消息是否完成，队列会暂停，待核对历史后继续。重新打开历史时从服务器读取运行状态，较新的 SSE 状态优先于延迟的 HTTP 快照。原生 Codex / Claude 回信由事件驱动。

## 验证

真实协议：Codex 与 OpenCode 各两个会话同时执行并返回各自标记；Claude Code 两个会话并发并分别调用测试 PDF 批注 MCP。真实前端组件配合模拟后端：四标签并发、隐藏面板保留、批注 A/B 定向派发、保留草稿、FIFO 三条消息、窄侧栏滚动、唯一控件 ID。UI 测试入口在打包前移除。

原生 macOS 补充验收：侧栏与终端采用直接设置尺寸，避免 WebView 的 JavaScript 展开动画停留在初始隐藏状态。工具执行与思考动画保留。字体变量补充系统字体后备，避免父级字体变量尚未定义时回退到浏览器默认衬线字体。独立原生验收实例验证了文件树、编辑器、终端、聊天输入区与收起/展开操作。
