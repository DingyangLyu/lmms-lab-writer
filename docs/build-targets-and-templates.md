# 多入口编译、模板与路径迁移

## 中英文分别编译

打开项目后，顶部编译按钮左侧可选择编译目标。在“设置 → Build”管理多个目标，每个目标有：名称、主文件、引擎、工作目录、输出目录。入口不必叫 main.tex：main_zh.tex / main_en.tex，或 zh/main.tex / en/main.tex 都可以。

例如：

| 目标 | 主文件 | 引擎 | 工作目录 | 输出目录 |
| --- | --- | --- | --- | --- |
| 中文 | zh/main.tex | XeLaTeX 或 Tectonic | zh | build/zh |
| 英文 | en/main.tex | 模板指定引擎／自动 | en | build/en |

编译后分别打开 build/zh/main.pdf 与 build/en/main.pdf。顶部显示的当前目标决定编译对象，不随编辑器标签误切换；同名 PDF 根据完整相对路径定位。两个目标不能指向相同的最终 PDF，以免相互覆盖。

配置在项目 `.writer/latex.json`，会进入 Writer Git 版本。所有路径相对于项目目录；移动或复制项目无需改绝对路径。旧版的全局主文件选择仅作为首次迁移提示，不再写回全局配置。扫描递归寻找实际文档入口，跳过缓存、依赖和 drafts 备份目录；需要编译备份／特殊入口时可手动添加路径。

## 编译器

引擎选择支持 auto、pdfLaTeX、XeLaTeX、LuaLaTeX、latexmk、Tectonic。自动模式会识别 `% !TEX program = ...`、中文、ctex/fontspec 等标志及常见 input/include 内容；每个目标可明确覆盖引擎。

先探测当前系统 PATH，再查实际安装的 TeX Live 年份目录、TinyTeX 架构目录和用户安装位置；不依赖当前用户账号或某一年份。只将能执行并报告版本的程序判为可用。设置里的“本机编译器”可重新探测、指定本机路径；本机绝对路径不写入项目配置，失效时重新自动查找。

有 latexmk 时用它管理多遍编译；否则按所选引擎运行，检测 BibTeX/Biber 并完成交叉引用轮次。Tectonic 使用其自己的参数，不混用传统 TeX 参数。编译在临时输出目录进行，成功后发布 PDF、SyncTeX 和辅助文件；失败保留上一份 PDF，不把旧文件冒充新结果。临时编译缓存不计入论文 Git 快照。

为了让输出位置由目标配置确定，latexmk 不自动执行 `.latexmkrc`，并关闭 shell escape；依赖特殊构建脚本或 shell escape 的模板需另行配置工作流。换电脑仍需安装 LaTeX 环境和所需字体／宏包；自动查找路径不等于自动安装所有依赖。Windows/Linux 路径逻辑已实现，但本次真实编译验收在 macOS 上完成。

## 模板导入

首页或顶部“导入模板”支持 ZIP 与完整文件夹。选择下载好的官方模板、存放目录和新项目名称，即可保留配套 `.tex/.sty/.cls/.bst/.bib` 与图片，创建新项目并打开。适用于 ICLR 等 LaTeX 模板，不内置或假定某一年度的会议样式，也不会覆盖当前论文。模板不是只导入一个 `.tex` 文件。

已有目标目录会拒绝覆盖；ZIP 越界路径、符号链接和过大的展开内容会拒绝导入。导入只复制文件，不执行模板脚本。服务器与 SSH 编译按本次要求暂不加入。

## 聊天中的文件链接

Codex / OpenCode 的 Markdown 文件链接在中间编辑区打开，支持相对路径、项目内绝对路径、file://、行号（#L12 或 :12:3）与 PDF 页码（#page=3）。网页链接仍交给系统浏览器。窗口级导航保护阻止本地文件 URL 替换 Writer 主页面，避免点击“PDF 已重新编译”导致界面重新载入。
