# 自适应输入框、对话重命名、大纲与 Claude Code

## 输入框

OpenCode、Codex 和 Claude Code 使用同一套边框、字体、输入区与工具栏样式。文字增加时自动增高；输入区连同工具栏最多占后端面板高度的一半，超过后在输入框内部滚动。删除文字会缩回；窗口或侧栏宽度改变时重新计算换行与高度。历史消息与输入框处于同一纵向布局，输入框增高时历史区让出空间。

Enter 发送，Shift+Enter 换行；中文输入法的候选确认仍由输入法处理。输入末尾始终保持可见；浏览旧消息时不会因打字强制跳到历史底部。

## 重命名

打开各后端的“历史”（OpenCode 用会话标题左侧的返回箭头），点击对话旁的铅笔，输入新名称并点击对勾保存。Codex 名称调用原生 thread/name/set；OpenCode 使用 session.update；Claude Code 的名称存入 Writer 的本机历史索引。请求失败时保留旧标题并显示错误。名称不是临时展示，重开应用后仍可读取。

## 左侧大纲

FILES 面板中，项目文件列表和“大纲”各自可收起。大纲按章、节、子节分层，并显示带标题的图表和 input/include 入口。章节旁的小箭头折叠子项，标题栏“折叠/展开”控制全部章节，点击条目跳到对应源码行并展开挡住该位置的编辑器折叠。

大纲显示当前 TeX 文档；正在看 PDF 或其他文件时显示当前编译目标的主文档。输入中的未保存文字会即时反映到大纲。它不是完整 TeX 解释器：宏动态生成的章节不会展开；input/include 目前显示为入口位置，需打开对应子文档查看其中章节。

## Claude Code

右侧新增独立的 Claude Code 标签，直接调用本机 CLI，沿用 CLI 的登录和模型配置，不复制凭据。模型菜单来自本机 CLI 的初始化结果，显示实际映射名称。本机当前默认模型映射为 Kimi K3，因此使用的是 **Claude Code 执行环境 + 本机配置的 Kimi 模型**；这不等于自动开通官方 Claude 模型权限。

支持流式正文、thinking 和工具状态、源码选区引用、图片粘贴/选择/拖入、Markdown 文件链接、停止任务、对话历史和重命名。切换到其他后端不会停止当前任务。权限提供请求批准、自动编辑、无需审批与仅规划；权限请求可仅允许这一次或拒绝，AskUserQuestion 可以在面板回复。

“无需审批”使用本机 Claude Code 的 `bypassPermissions` 与 `--dangerously-skip-permissions`，普通工具执行不再逐项询问。项目会记住选择，恢复历史、后续消息、队列和协作委派使用面板所选权限。未选择过的项目仍使用“请求批准”，不会修改全局 Claude 配置。请在任务空闲时切换；运行中的任务使用启动时的模式。Claude 强制的组织策略、显式 ask/deny 规则、hooks，以及需要用户回答的问题仍由原生权限机制处理，Writer 不会把所有交互请求伪造为“允许”。参见 [Claude Agent SDK 权限说明](https://code.claude.com/docs/en/agent-sdk/permissions)。

每轮使用同一个原生 session ID 续聊（CLI 进程可以重新启动，--resume 保留上下文），不是每次创建无关联的新对话。Writer 历史保存在本机应用数据目录的 claude-sessions 下，按项目隔离；Claude CLI 仍保留自己的原生会话记录。退出应用会停止 Writer 启动的运行进程。

当前 Codex ↔ OpenCode 的 MCP 互相委派桥保持原有范围；新增 Claude Code 这次先提供独立执行后端，没有把第三方会话自动加入原有双向委派链。服务器和多人协作只调研，见 server-and-collaboration-research.md。

## 验证

本次覆盖三种输入框的长文本增高、最大高度、超长滚动、清空收缩、窄侧栏布局、大纲章节/图表与忽略注释、对话重命名保存及失败保留。Claude Code 实际调用测试包含两轮记忆续聊、图片颜色识别、拒绝写入和批准指定测试文件写入；使用隔离的临时项目，没有发送真实论文给测试会话。
