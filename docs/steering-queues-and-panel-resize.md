# 拖动面板高度、执行中指导与消息队列

## 拖动高度

右侧输入区顶部、左侧大纲顶部都有横向手柄。向上拖增高，向下拖缩小，最多占所属侧栏内容区的 50%；历史消息/文件列表会同步腾出空间。手动高度按比例保存在本机，换窗口大小后仍受半屏上限约束。双击手柄恢复默认：输入框恢复随文字自动增高，大纲恢复默认比例。手柄也支持键盘上下方向键调整、Enter/Home 恢复。

## 两种发送方式

三种后端的输入框上方都有“执行中发送”选择：

- **立即指导 · Steer**：把补充要求交给当前任务。Codex 使用原生 turn/steer 并校验正在执行的 turn ID；OpenCode 立即提交 prompt_async，在代理下一次处理输入时生效；Claude Code 通过原生流式协议中断当前步骤，再在同一会话接入新消息。已经完成的文件修改不会自动撤销。
- **排队 · Queue**：本轮结束后，按顺序发送待办消息。每条完成后才发送下一条，支持多条队列、上下调整顺序、移除、暂停和继续。空闲时发送按钮直接开启正常任务。

执行中仍能输入文字、粘贴/添加图片；停止按钮与发送按钮并列显示。中文输入法确认候选词不会触发发送，Shift+Enter 换行。

## 保存与异常处理

队列按后端、项目和对话 ID 隔离，保存消息文字、图片和当时引用的选区快照。加入队列成功落入本机 IndexedDB 后才清空输入框；存储失败则保留输入内容。消息收到后端接受响应后才从待发列表移除。

切换 Codex/OpenCode/Claude Code 标签不会停止当前后端或其队列。切换到另一个历史对话时，原队列仍归原对话；返回时可恢复继续，不会误发给新对话。

手动停止、执行失败或队列发送失败会暂停后续消息。应用重启后恢复的队列默认暂停，点击“继续队列”确认恢复；如果上次发送是否成功无法确认，先核对历史，再选择重试或移除，避免重复发送。每个对话最多保存 50 条待发消息。

引用的源码在排队期间若已改变，发送前检查会暂停该条并保留内容，要求重新选择引用，避免按失效位置修改论文。Steer 赶在本轮结束之后到达时，会保留输入并提示正常发送或排队。

## 验证

已在隔离的临时项目中对三个原生后端实测执行中补充要求，最终响应均遵循新指令。Claude 中断结果与接续结果分别处理，避免在第一个结果出现时关闭进程。OpenCode 使用异步接受接口，输入区不会因同步请求等待任务完成而锁住；完成计数只使用 session.status，避免兼容用 session.idle 通知重复推进队列。

队列状态机测试覆盖顺序、重复渲染、快速完成先于确认、失败保留、停止暂停、持久化恢复、图片快照、重排和移除；开发界面测试覆盖实际鼠标拖动、半屏限制、布局不重叠、三条队列逐条发送及重载恢复。
