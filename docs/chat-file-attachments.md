# 聊天文件附件

OpenCode、Codex、Claude Code 共用“添加附件”回形针按钮。点击可选择多个文件，也可拖入输入区或粘贴剪贴板中的文件。每条消息最多 6 个附件；普通文件单个上限 25 MB，PNG/JPEG/GIF/WebP 图片仍为 10 MB。

发送前会显示文件名、大小和移除按钮。文件可与图片混合发送，也能用于执行中指导和消息队列。一次选择多个文件时逐个导入：失败的文件单独给出原因，其余照常加入；超过 10 MB 或无法识别的图片会作为普通文件附加并提示。导入进行中再拖入或粘贴的文件会排队处理，不会被忽略。读取或发送失败时保留草稿；发送后的聊天历史以可点击的附件卡片展示，文件名含 `#`、`?` 也能打开。

未发送的输入与附件按项目和对话标签保存在本机（IndexedDB），切换项目、重启后恢复；只有草稿的新标签也会保留。

普通文件先复制到当前项目的 `.writer/attachments/<内容 SHA-256>/<原文件名>`，再把相对路径交给 Agent。这样项目外的文件也能由项目内的工具读取，原文件移动后历史与队列仍有可用副本。文件内容不长期放在前端内存中。同名但内容不同的文件隔离保存，完全相同的文件复用副本。发送前检查副本是否仍存在且内容一致。

副本设为只读，编辑器以只读方式打开 `.writer/` 下的文件（`.writer/latex.json` 除外），文件树不显示 `.writer/`。若副本仍被其他程序改动，再次添加原文件时会把改动后的版本移到同目录的 `modified-<时间>/` 并恢复原内容，历史链接重新可用。

TXT、LaTeX、BibTeX、PDF、Office 文档、CSV、代码、压缩包等可作为普通附件添加。具体内容由 Agent 使用本机可用的读取或解析工具处理；可添加文件不等同于所有模型都原生支持所有格式。支持的图片继续走视觉输入，不转换为普通文本引用。

“移除附件”只解除当前草稿的关联，不删除磁盘副本，以免破坏已经发送的历史或排队中的消息。目前不自动清理副本：历史分散在各后端自己的存储中，无法可靠判断副本是否已无引用。

附件副本**不进入** Writer 的本地 Git 版本（`.writer/` 除批注、修订、冲突与构建目标外均被排除），删除后无法从版本历史恢复。Writer 会把 `.writer/`、`.lmms_lab_writer/` 写入项目仓库的 `.git/info/exclude`（仅本机、不提交），Git 面板不再列出它们，“Discard All”也不会删除它们；不会自动上传网盘或推送远程 Git。

验证：前端附件、选区、队列及历史回归测试；原生复制、中文文件名、同名文件隔离、大小限制、内容校验及符号链接测试；桌面端选择项目外 TXT，Codex、OpenCode / Kimi、Claude Code 均实际读取并正确返回文件中的测试标记，历史附件链接可打开。
