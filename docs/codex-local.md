# 本机 Codex 登录接入

## Codex 执行后端（文献检索推荐）

打开项目后，点击右上角机器人按钮，在右侧面板顶部选 **Codex**。这会启动本机安装的 `codex app-server`，直接使用 Codex 自己的会话、工具和当前登录；Writer 不读取、复制或储存 `auth.json`。模型选项由当前账号的 `model/list` 返回，默认选择账号实际可用的模型。这里的网页检索设置为 live，仅作用于 Writer 启动的 Codex 进程，不更改用户的全局 Codex 配置，也不为沙箱内的终端命令额外开放网络权限。

可以点击“填入文献检索任务”，再发送已填入的提示词：它要求逐篇核对题名、作者、年份与 DOI／原文链接，复用或补充 `.bib` 条目，在相应 `.tex` 论断旁插入 `\cite{key}`，并检查引用键与编译结果。搜索和文件修改过程会显示在聊天里，来源链接可以点击检查。选中 `.tex` 内容再发送修改要求时，Writer 会将文件位置和原文附在用户消息后面；聊天中的“已引用”指这份选区上下文，并不代表论文已经插入引文。

对话按项目保存在本机 Codex 会话中。关闭 Writer 后会恢复上次会话；右上角“历史”列出该项目的 Writer 对话，点击可读取旧消息。“新对话”会另开会话，不删除旧记录。需要额外权限时面板会显示确认请求。

输入框下方的“权限”菜单有四档：**只读**（修改须批准）、**请求批准**（默认，可直接修改当前项目，越界时询问）、**自动审查批准**（仍保留工作区沙盒，由 Codex 自动审查符合条件的审批请求）和**完全访问**（无沙盒、无审批）。选择会在该项目保存，从下一条消息起应用于当前 Codex 会话；切换权限不会清空对话历史。权限语义以 [Codex 官方沙盒说明](https://learn.chatgpt.com/docs/sandboxing)为准。

下面的旧方式仍可使用，但它是在 **OpenCode 执行后端**中调用 Codex 订阅模型，搜索与工具仍由 OpenCode 提供。

## OpenCode 中使用 Codex 模型

在 Writer 的 Agent 输入框下方点击模型名称，选择 **Codex（本机登录）** 分组下的模型。Kimi K3 仍可随时切回。

插件每次请求读取 `~/.codex/auth.json`（设置了 `CODEX_HOME` 时使用该目录），并仅向 OpenAI 的 Codex 响应端点发送访问令牌。不会复制或自行轮换 Codex 的 refresh token，也不会把令牌保存到项目中。

模型名称来自本机 `models_cache.json` 中公开列出的模型，保留原始 ID，不使用旧多账号插件的模型名称重映射。模型实际可用性受当前账号的订阅和权限约束。若 Codex 更新了模型列表，重启 Writer / OpenCode 后生效。推理强度提供兼容当前 OpenCode SDK 的 low、medium、high、xhigh。

如果提示登录过期，请在本机 Codex 中完成登录或一次请求，让 Codex 刷新认证缓存，然后在 Writer 重试。若模型列表尚未缓存，先打开 Codex，再重启 Writer。

安装文件位于 `~/.config/opencode/lmms-codex-local/`，由 OpenCode 的两个全局配置文件显式加载；OpenCode auth 存储仅加入不含真实令牌的连接标记。既有 Kimi 配置和其他账号均保留。
