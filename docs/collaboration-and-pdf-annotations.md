# 会话协作与 PDF 批注

## 双向协作

在同一项目里分别打开 Codex 和 OpenCode 的目标会话（历史会话也可以）。会话上方显示完整 ID，点击即可复制。两边“允许协作”开启后，对任一模型说：

> 请把这个检查任务交给 `opencode:ses_…`，让它核实引用；收到结果后再继续修改。

反过来把 `codex:…` ID 交给 OpenCode 即可。MCP 自动接入 Writer 管理的两个后端进程，不写入全局 Codex / OpenCode 配置，也不读取或复制登录密钥。

工具为 `writer_list_conversations`、`writer_delegate`、`writer_get_task`、`writer_get_pdf_annotations`、`writer_resolve_pdf_annotation`。工具会得到当前会话 ID；用户无需手写工具参数。委派立即返回任务号，目标忙时排队，完成或失败会在发送方当前轮次结束后自动发起回信轮次。内部靠完成事件和请求结束触发，不需要模型轮询。消息直接进入对方会话记录，输入框里未发送的草稿不会被替换。

每个目标沿用其选定模型与权限。自动任务开始前会等待编辑器保存确认；保存失败不启动。项目范围隔离，不接受未在 Writer 打开过的任意外部会话。每个发送方最多 4 个未完成回信的委派；委派与自动回信轮次不能继续套娃委派，以避免循环。可以在“协作”展开任务状态、结果，取消仍在排队的任务；已运行任务用对应面板的停止按钮。需要人工审批的任务仍会等待审批，不会自动放宽权限。

任务记录存于应用数据目录的 `writer-bridge-tasks.json`。重启后保留记录，但不会自动重放未完成任务，避免重复改稿；未完成项会显示中断，需核对目标历史后重新委派。自动回信需要 Writer 保持打开。

## PDF 批注

打开项目中的 PDF，选择“高亮批注”或“下划线批注”，拖选文字并填写修改要求，点击“保存批注”。跨行选区保存为多个矩形，缩放后保持对齐。顶部“保存 Git 版本”左侧的“批注”下拉面板可查看、搜索、编辑、标为已解决，以及跳转对应 PDF / `.tex` 段落。面板可整体收起；每条批注可单独折叠，也有全部展开／全部折叠按钮。已解决项显示绿色勾选，解决后自动折叠，但保留完整处理历史。

批注保存于项目 `.writer/pdf-annotations.json`，包含页码、选文、要求、标记位置、PDF 指纹、源码路径和段落上下文。该文件纳入普通 Git / Writer Git 版本。未提交的新批注草稿也暂存在本机，PDF 刷新后可恢复。

点击“交给 Codex”或“交给 OpenCode”发送全部待处理批注，也可以在单条批注上只发送这一条。AI 用 MCP 读取完整批注和当前源码。优先用 SyncTeX 定位；缺少 SyncTeX 时只接受唯一的文本段落匹配。无法可靠定位就显示“源码位置待核对”，保留原文和坐标，要求模型核对而非猜测行号。

源码改变后，工具返回 `sourceChanged` 提醒重新定位。PDF 重新编译、指纹改变后，旧坐标不再直接覆盖新页面，以免标错段落；批注内容和原始选文仍保留在列表里，可据此核对位置。批注当前是 Writer 中的项目批注，不会直接写进 PDF 文件，因此外部阅读器不会显示这些标记。扫描版无文字层的 PDF 尚不支持拖选文字批注。

普通 PDF 点击不会跳走；`⌘/Ctrl + 点击` 使用 SyncTeX 跳转源码。

## 验证

测试项目独立于用户论文。验证了 Codex → Kimi → Codex 自动回信、Kimi → Codex → Kimi 自动回信；真实 PDF 的高亮／跨行下划线、SyncTeX 源码定位、MCP 读取要求后指定句子修改；队列忙闲、重复请求、权限／项目边界、批注持久化和源码变化检测有自动化测试覆盖。

协议参考：[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。


## 自适应缩放与强制版本记录

PDF 默认“适应宽度”，持续跟随容器、窗口、侧栏和分屏宽度。页面尺寸来自 PDF.js，横向页面也按实际宽度适配；不同屏幕的像素密度变化会更新渲染清晰度。`+`、`−` 或百分比按钮进入手动缩放，点击“适应宽度”可恢复自动跟随。

创建／编辑批注立即保存 Git 版本；提交给 AI 前保存包含批注的修改前版本；手动或 MCP 标记解决时保存包含文稿和已解决状态的修改后版本。这些记录不等待 15 分钟周期。旧批注在首次打开新版时保存一份当前基线，无法还原旧版没有记录的历史。批注和事件记录跟随 `.writer/pdf-annotations.json` 一并入库。

版本继续使用独立本地 `refs/writer/snapshots`，不改动当前分支或暂存区。每次事件的 Git 号从提交记录读取，避免为存储自己的提交号制造额外未保存修改。批注面板可按待处理／已解决筛选，展开“版本与处理历史”后点击 Git 号看差异。

若 Git 保存失败，批注变更回退并显示失败原因，不提前显示已解决；正文文件不回退。编辑已经解决的批注要求会重新打开它，并保留原来的解决记录。周期快照也会继续保存批注文件，即使普通 `.gitignore` 忽略 `.writer/`。
