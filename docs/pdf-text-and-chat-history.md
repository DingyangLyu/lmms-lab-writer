# PDF 选文与临时对话 / 历史

## PDF 字体映射

已复现的根因是旧论文 PDF 中嵌入的 `STHeiti` 粗体中文字体使用 `Identity-H`，但缺少 `ToUnicode`，字体子集中也没有 Unicode cmap。PDF 绘制所需的字形仍然存在，所以肉眼看正常，而 PDF.js / Poppler 提取到的是字形编号。普通正文使用的字体含有正确的映射。

`pdf_prepare_preview` 在后台解析 PDF，对缺失映射的 TrueType 字体查找本机相同 PostScript 名称的字体，并逐个比对实际嵌入字形的轮廓与 units-per-em。只有校验一致才建立 CID → UTF-16BE 映射，写入应用缓存中的预览副本。原 PDF、TeX、排版和字体轮廓不改写；原 PDF 指纹继续保留，批注坐标不用迁移。正常字体已有的映射不覆盖。无法可靠匹配时显示提示，批注草稿中也可展开“核对／修正选中文字”。

字体查找支持系统字体目录；macOS 还读取系统已下载的 MobileAsset 字体目录，不依赖 Python、Poppler 或额外安装的命令行程序。PDF/字体解析在后台线程运行，成功的预览副本按原始文件内容哈希缓存。

旧批注不会简单按“乱码字形”猜测替换。启动项目时只对疑似错误选文检查 Writer 私有 Git 版本：原 PDF 指纹必须与批注一致、字体字形必须匹配、解码后的文字必须在创建批注时保存的 TeX 上下文里唯一出现，才能恢复该片段。备注、已解决状态和历史定位不变，恢复操作单独创建 Git 版本；无法确认的记录保持原状。

验证使用了论文历史 PDF：PDF.js 的指纹前后一致，加粗“运行状态与调度。”提取正确；Poppler 页面渲染逐像素一致；项目副本里的 3 条旧选文成功恢复，重复执行不再修改。

## 新对话与历史入口

- 顶部的后端按钮打开临时新对话，不再用它代替历史入口。
- 空白临时标签没有原生会话 ID；发送消息才创建实际会话。重复点击同一后端复用其空白标签。
- 切换到其他标签时丢弃未输入、未执行、没有排队消息的临时标签；已有草稿或任务继续保留。
- 空白标签不保存到下次启动；待派发任务单独持久化并在恢复后暂停。
- 对话标签栏旁的“历史对话”打开统一历史窗口，支持三个后端、项目内搜索、重命名、打开已有对话。已经打开的历史会话直接聚焦原标签，不中断其任务。
- OpenCode 的历史用 `message?limit=1` 确认实际有消息，兼容只有图片的消息，过滤旧版留下的空白记录；读取失败不会误报为“没有历史”。Claude 同样过滤没有事件的空会话。Codex 保留现有项目与 originator 筛选，并支持下一页游标。
- 恢复历史时保留原生会话身份，等待服务器状态加载后才允许发送，避免把尚未载入的历史误判成空白草稿或误向正在运行的任务直接发送。

原生验收验证：打开未发送的新 OpenCode 对话时服务器仍只有原来的 2 个会话；从历史打开后读回原消息；发送独立的 `HISTORY_OK` 测试消息后才新增第 3 个历史会话。
